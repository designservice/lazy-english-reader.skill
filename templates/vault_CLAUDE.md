# CLAUDE.md — Obsidian Vault AI 操作指南

这个 vault 由 AI agent（Claude Code / Codex / Cursor / Gemini CLI / 其他 agent）协同维护。本文件是给 AI 看的导航说明。文件名保留为 `CLAUDE.md` 是为了兼容 Claude Code；其他 agent 可把它当作目录级 context file 读取。

## Vault 结构

```
.
├── CLAUDE.md           ← 本文件
├── index.md            ← 人类可读的 MOC
├── 书库/            ← 按书组织
│   └── <书名-作者>/
│       ├── CLAUDE.md   ← 本书的特定上下文
│       ├── index.md    ← 本书 MOC
│       ├── 00_全本中译/ ← 整书翻译产物（线 A，可选）
│       ├── 01_章节精读/ ← 每章一份 markdown：第一人称叙事 + 嵌入式精译 + 编辑解读
│       └── 02_主题笔记/ ← 本书内的主题归纳（线 C）
└── 主题/                ← 跨书概念笔记
```

## 命名约定

- **文件名**：中文优先，连字符或下划线分隔，不要空格
- **双链**：用 `[[文件名]]` 或 `[[文件名|显示文本]]`
- **frontmatter**：所有笔记顶部 yaml，至少包含 `tags` 和 `created`

## 给 AI 的行为约定

1. **保留人类批注**：任何标 `<!-- HUMAN -->` 的段落不要修改
2. **双链优先于复制**：如果某概念在 `主题/` 已有笔记，新笔记应链过去而不是重写
3. **frontmatter 不破坏**：编辑笔记内容时保持 yaml frontmatter 完整

## 章节精读文件规范

每本书的 `01_章节精读/` 下，**一章一个 markdown 文件**（平铺，不嵌子目录）。文件内部结构：

1. yaml frontmatter（book/chapter/chapter_title/pages/status/voice/tags/created）
2. `# 第 N 章 — 中英标题`
3. 若干 2-3 字小标题分段（标题应来自章节里具体物件/场景，不要"核心内容"、"主要论点"这类通用学术抬头）
4. **以作者本人的第一人称声音**用中文复述章节脉络
5. 关键原文短句以引用块嵌入，紧跟一行中文对照 + 页码：
   ```
   > "short English original"
   > 中文（p.XX）
   ```
6. `## 编辑解读` — 笔记整理者的几条补充。**描述书中内容/补充背景**，不评论作者技巧。3-5 条，每条只在"读者不知道这点会读不懂"时才写
7. `## 我的批注` — 留 `<!-- HUMAN --> ... <!-- /HUMAN -->` 块给用户写
8. `## 链接` — 上下章、章节地图、相关主题

## 跨书概念

当 `01_章节精读/` 反复出现某概念（如"采访技巧"、"非虚构写作"），提到 `主题/<概念名>.md`，所有引用处用 `[[主题/<概念名>]]`。
